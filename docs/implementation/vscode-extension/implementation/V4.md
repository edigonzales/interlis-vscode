Java besitzt `EditorAssistanceService` mit revisionsgebundenen Single-Source-
Editplänen, vollständigen AST-/Token-kontextabhängigen Completion-Slots und
Metaattributkatalog. Der LSP transportiert native Snippets und versionsgebundene
WorkspaceEdits. MODEL-Header werden im Client generisch vor Suggestions geschützt;
native Placeholder-/Cursoraktionen erfolgen vor Extension-Host-Buchführung.
Importlöschung verlangt vollständige fehlerfreie Analyse und gebundene Referenzen;
END-Korrektur wird bei unvollständiger Syntax nicht angeboten. `context.only` wird
berücksichtigt. Java-Templates sind für beide Sprachversionen materialisiert geprüft.

`interlis-documentation` projiziert ausschliesslich `CompiledSchema` in einen
immutablen Katalog. Typinformationen sind typisiert, rekursive Strukturen bleiben
Referenzen. DE/FR/IT/EN, zehn Headeroverrides, drei Inheritancemodi, echte
Markdown-/HTML-/OOXML-Renderer und GraphML aus dem neutralen DiagramDocument sind
implementiert. Bestehende Mermaid-/PlantUML-Renderer bleiben die einzige Quelle
dieser Graphtexte. Element-/Text-/Render-/Transportlimits sind explizit; kein AST,
Compilerlauf, Datei-IO oder Netzrenderer im Renderer.

`interlis/export` prüft Version, Snapshot, aktuelle Source-Revisions und vollständige
Kompilation. Host prüft erneut Quelle/Server/Generation, zeigt native Format-/
Options-/Save-Dialoge, verwirft veraltete Ergebnisse und schreibt über temporäre
Datei mit abschliessender Frischeprüfung. Markdown nutzt die native lokale
Vorschau, HTML einen skriptlosen Webview. Templates sind literal, begrenzt und
cancellable; Loopback-HTTP gehört nur zur kontrollierten GUI-Fixture.
